The problem

An LLM knows the world, not your organisation

Private

Your contracts, emails and meeting notes were never in its training data.

Stale

Training stops at a cutoff date. Your data changes every hour.

Too big

Millions of documents will never fit into a model's context window at once.

The fix: find the few pieces that matter at question time and hand them to the model. This is called grounding.

How we got here

Six generations of enterprise retrieval

01

Keyword search

Match exact words (BM25). Fast, but misses synonyms.

02

Vector RAG

Turn text into meaning vectors; paste the closest chunks into the prompt.

03

Hybrid + rerank

Combine keyword and vector results, then re-score the best.

04

GraphRAG

Add entities and relationships for multi-hop questions.

05

Agentic retrieval

The model plans, searches several sources, checks, and retries.

06

Memory + MCP

Persistent memory, plus standard plugs into any system.

Newer generations don't replace older ones. Production systems stack 03 to 06: hybrid search underneath, graphs and agentic planning on top, memory around it all.

Pattern 2 · Hybrid search

Two searches, one ranked shortlist

Keyword (BM25)

Exact words, codes and names, e.g. “INV-2231”

Vector

Meaning and paraphrase, e.g. “money we owe the supplier”

Fusion

Reciprocal Rank Fusion merges both ranked lists into one.

Reranker

A second model re-reads each shortlisted chunk against the question and re-scores it.

Top few to the LLM

Small, highly relevant context.

Why it's the default: keyword search catches the invoice number; vector search catches the paraphrase. Reranking puts the genuinely useful chunks first.

Comparing patterns

Four approaches side by side

Approach Best for Weak at Cost
Vector RAG Fuzzy “what does our policy say about…” questions Exact codes, names and numbers Low
Hybrid + rerank Most enterprise search: the sensible default Questions spanning many documents Low to medium
GraphRAG Multi-hop links and themes across a whole corpus Fast-changing data; keeping the graph current High to build
Agentic retrieval Complex, multi-part questions across sources Latency and token cost per question Medium to high per query

Pattern 4 · Agentic retrieval

Retrieval becomes a reasoning loop

1 · Plan

Split the question; choose sources.

2 · Search

Run sub-queries in parallel.

3 · Reflect

Enough good evidence? If not, loop back.

4 · Synthesize

Merge, rank, answer with citations.

Example trace

“Compare our UK and India leave policies and flag what changed this year.”

Plan Two sub-queries: UK policy, India policy.

Search Both run at once over the HR site and policy index.

Reflect India hit is an old draft, so search again for the current one.

Synthesize Side-by-side answer, every claim cited.

Pattern 5 · Memory

Agents remember at four timescales

Working memory

The context window: this prompt, retrieved chunks, tool results.

One model call

Session memory

The conversation so far, summarised when it grows long.

One chat

Long-term memory

Facts and preferences the agent saves about a user.

Across chats

Organisational knowledge

Indexes, graphs and systems of record, shared and governed.

Permanent

The top layer is tiny and expensive; the bottom is huge and cheap. Good agents move only what's needed upward, just in time.

How Copilot answers

Five steps from prompt to grounded answer

1

Prompt

You ask in Word, Teams, Outlook or Copilot Chat.

2

Ground

Pulls context from Microsoft Graph and the semantic index, limited to what you can access.

3

Generate

The enriched prompt goes to the large language model.

4

Check

After generation, Graph and index are consulted again; safety and compliance filters run.

5

Respond

Answer, citations and any app commands return to your app.

Microsoft calls it grounding, not RAG, but step 2 is exactly retrieval-augmented generation. The difference: the index, permissions and security are run for you.

Doing it well

Six habits of production-grade apps

01

Trim by permission at query time

Filter results by the user's identity before the model sees them.

02

Chunk with structure

Split on headings and sections; keep titles and metadata with each chunk.

03

Default to hybrid + rerank

Add graphs or agentic loops only when the questions demand it.

04

Always cite sources

Citations let users verify answers and expose bad retrieval quickly.

05

Evaluate continuously

Test sets that score retrieval recall, groundedness and answer quality.

06

Fix data hygiene first

Oversharing and stale content become wrong answers. Clean before you index.

Cheat sheet

Ten terms worth knowing

Grounding: giving the model real source data before it answers.

RAG: retrieve relevant chunks, add them to the prompt, then generate.

Chunk: a passage of a document, sized to hold one complete idea.

Embedding: a list of numbers representing a chunk's meaning.

Vector index: a store that finds the nearest embeddings fast.

Hybrid search: keyword and vector search run together, results fused.

Reranker: a model that re-scores a shortlist for true relevance.

GraphRAG: RAG over an LLM-built graph of entities and relationships.

Agentic retrieval: the model plans, searches, checks and retries.

MCP: an open protocol for connecting agents to tools and data.
